# Eightcore — Data Model

Status: implemented incrementally with Drizzle + versioned SQL migrations. **Phase 2 tables (live):** §4.1 identity, `workspaces`, `workspace_members`, `workspace_invitations`, `projects`, `project_members`, `activity_events`, `audit_log`, `outbox_events` (`drizzle/0000_init.sql`, `0001_invariants_and_privileges.sql`). Everything else is planned. Last updated 2026-10-13.

## 1. Conventions

| Convention | Rule |
|---|---|
| Primary keys | `id uuid primary key default gen_random_uuid()` |
| Tenancy | Every workspace-owned table has `workspace_id uuid not null` |
| Cross-row integrity | Child → parent references use **composite FKs** `(parent_id, workspace_id) → parent(id, workspace_id)`. Every parent table has `unique (id, workspace_id)` to make this possible |
| Timestamps | `created_at timestamptz not null default now()` and `updated_at` (trigger-maintained) on mutable tables |
| Soft delete | `archived_at` (archive), `deleted_at` (trash). Partial indexes `WHERE deleted_at IS NULL` |
| Enums | Postgres enums for stable, small sets (roles, priority). Lookup tables for user-configurable sets (statuses, tags, field options) |
| Ordering | `position text not null` (fractional index), indexed together with its parent |
| Naming | `snake_case`, plural tables, `<table>_<cols>_idx` / `_uq` / `_fk` |
| Migrations | Generated by `drizzle-kit generate`, reviewed, and committed in `drizzle/`. Hand-written SQL migrations for triggers, functions, roles, and RLS. Never edited after merge |

## 2. Why composite foreign keys

```sql
-- every parent exposes (id, workspace_id) as a key
alter table task_lists add constraint task_lists_id_ws_uq unique (id, workspace_id);

-- every child carries workspace_id and references both columns
create table tasks (
  id uuid primary key default gen_random_uuid(),
  workspace_id uuid not null references workspaces(id),
  list_id uuid not null,
  foreign key (list_id, workspace_id) references task_lists(id, workspace_id)
  ...
);
```

With this pattern, a task in workspace A **cannot** point at a list, parent task, status, assignee membership, tag, or custom field in workspace B, even if application code has a bug. This is the database half of "prevent unauthorized cross-workspace access".

### 4.3 Workflows

> **As built (Phase 3a):** statuses belong to a **list** (`list_statuses`), not to a shared workflow, so every list's statuses can be customised independently. A new list copies its statuses from a template (`src/modules/lists/templates.ts`: *Agency delivery*, *Simple*). `tasks.status_id` references `(id, list_id)` of `list_statuses`, so a task can only use its own list's statuses. Transition rules (below) arrive in Phase 5 and will be keyed on list statuses. Task dates are calendar dates (`start_date`, `due_date` as `date`), so deadlines never shift across time zones.


| Table | Columns | Constraints |
|---|---|---|
| `workflows` | id, ws, name, is_template, created_by | |
| `workflow_statuses` | id, ws, workflow_id, name, key, category `status_category` (backlog/unstarted/active/review/done/cancelled), color, position, is_initial | Unique (workflow_id, key). Unique (id, workflow_id). Exactly one `is_initial` per workflow (partial unique index) |
| `workflow_transitions` | id, ws, workflow_id, from_status_id null (= any), to_status_id, min_project_role, require_comment bool, required_field_ids uuid[], creates_qa_cycle `qa_result` null (pass/fail) | Unique (workflow_id, from_status_id, to_status_id). FKs (from/to, workflow_id) → statuses(id, workflow_id), so a transition cannot reference another workflow's status |

If a workflow has **no** transition rows, any move is allowed (simple mode). Once any row exists, only listed transitions are allowed (strict mode). The agency template ships in strict mode.

### 4.4 Tasks

| Table | Columns | Constraints / indexes |
|---|---|---|
| `tasks` | id, ws, project_id (denormalized from list), list_id, workflow_id, status_id, parent_task_id null, number (per-project sequence → `WEB-142`), title, description jsonb, description_text, priority `task_priority` (urgent/high/normal/low/none), start_at, due_at, due_has_time, estimate_minutes, position, version int, created_by, completed_at, archived_at, deleted_at, search tsvector (generated) | FK (list_id, ws). FK (status_id, workflow_id) → workflow_statuses(id, workflow_id). FK (parent_task_id, ws) → tasks(id, ws). `check (parent_task_id <> id)`. `check (char_length(title) between 1 and 500)`. Unique (project_id, number). Indexes: (list_id, status_id, position), (workspace_id, due_at) where not deleted, GIN(search), GIN(title gin_trgm_ops) |
| `task_assignees` | ws, task_id, user_id, assigned_by, assigned_at | PK (task_id, user_id). FK (task_id, ws). **FK (workspace_id, user_id) → workspace_members** (assignee must be a member). Index (user_id, workspace_id) for My Work |
| `task_watchers` | ws, task_id, user_id | PK (task_id, user_id), same FKs |
| `tags` / `task_tags` | tags: id, ws, project_id null, name, color. task_tags: ws, task_id, tag_id | Unique (workspace_id, project_id, lower(name)) |
| `task_relations` | id, ws, source_task_id, target_task_id, type (`blocks`, `relates_to`, `duplicates`) | Unique (source, target, type). `check (source_task_id <> target_task_id)`. Both FKs composite with ws |
| `checklists` / `checklist_items` | checklist: id, ws, task_id, name, position. item: id, ws, checklist_id, text, done_at, assignee_id, position | |
| `task_status_changes` | id, ws, task_id, from_status_id, to_status_id, actor_id, changed_at | Append-only. Drives cycle-time reporting without scanning activity JSON |

**Hierarchy invariants** (enforced by a `BEFORE INSERT/UPDATE` trigger plus service checks):

- A subtask's `list_id` equals its parent's (moving a parent moves its subtree).
- No cycles: a recursive CTE from the new parent must not reach the task itself.
- Depth ≤ workspace setting (default 5).
- Concurrent re-parenting is serialized with `pg_advisory_xact_lock(hashtext(workspace_id::text))` for the duration of the check.

**Dependency invariant:** a new `blocks` edge must not create a cycle (recursive CTE under the same advisory lock).

### 4.7 QA and delivery

| Table | Columns | Notes |
|---|---|---|
| `qa_cycles` | id, ws, task_id, cycle_number, started_at, started_by, result (`pending`/`pass`/`fail`), concluded_at, concluded_by, environment_url, build_ref, summary | Unique (task_id, cycle_number). **Never updated after conclusion** (trigger blocks updates once `result <> 'pending'`). Notes are `comments.kind = 'qa_note'`. Evidence is `attachments.qa_cycle_id` |

Example flow: *Ready to Test → Testing in Staging* opens cycle N. *Testing in Staging → In Development* (rule `creates_qa_cycle = fail`, `require_comment = true`) concludes cycle N as **fail**, with a note and evidence. A later re-entry opens cycle N+1. *Testing in Staging → Final Review* concludes as **pass**.

> **As built (Phase 3b):** `tags` are per project (`project_id` required, unique `lower(name)` per project); `task_tags` carries `project_id` with composite FKs to both the task and the tag, so a task can only use its own project's tags. `comments.body` is plain text (mentions are stored in `comment_mentions`; a soft-deleted comment keeps a placeholder only while it has replies, and its files are removed). `task_watchers` (ws, task_id, user_id) records who follows a task. `notifications` has `type` (`assigned`, `mentioned`, `commented`, `status_changed`), `task_id`, `actor_id`, `data` jsonb and `read_at`; recipients are limited to people who can see the project. `attachments.comment_id` references `(id, task_id)` of `comments`, so a comment's file belongs to the same task. Uploads are capped by `MAX_UPLOAD_BYTES` (default 4 MB).

> **As built (Phase 3c):** `task_dependencies` (ws, blocking_task_id, blocked_task_id, created_by) with composite FKs to both tasks in the same workspace, `check (blocking <> blocked)` and a trigger (`task_dependencies_no_cycles`) that refuses loops; the service also serialises changes per workspace with an advisory lock. Links can cross projects; people only see links to tasks in projects they can see. Custom fields: `custom_fields` (project_id, list_id null = whole project, name unique per project, type `custom_field_type`), `custom_field_options` for dropdowns, and `task_field_values` with one typed column per kind and `check (num_nonnulls(...) = 1)`. FKs keep the task, field and option in the same project/field; deleting an option clears the values that used it. Link values only accept http(s) URLs.

## 5. Search

```sql
search tsvector generated always as (
  setweight(to_tsvector('simple', coalesce(title,'')), 'A') ||
  setweight(to_tsvector('english', coalesce(description_text,'')), 'B')
) stored
```

Comments are searched through a separate `comments.search` column, unioned in the query. `pg_trgm` covers typo-tolerant title lookup in the command palette.

## 6. Default seed data

- The **Agency Delivery** workflow template: Backlog (backlog) → To Do (unstarted) → Ready for Dev (unstarted) → In Development (active) → Ready to Test (review) → Testing in Staging (review) → Final Review (review) → Push to Production (active) → Accepted (done), plus Cancelled (cancelled). Strict transitions, including the QA-fail edge back to In Development.
- A demo workspace with sample users for each role (development only, never in production).
